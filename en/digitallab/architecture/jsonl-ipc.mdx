DigitalLab's core communication uses the JSON Lines (JSONL) protocol: each line is a complete JSON object, transmitted in UTF-8 over `stdin/stdout`. The Electron main process sends commands to the Python child process's `stdin`, and Python returns responses, events, and state frames on `stdout`.

## Message frame format

### Request frame (main process → Python)

| Field | Type | Description |
| --- | --- | --- |
| `cmd` | `string` | Command name |
| `requestId` | `string` | Generated by `crypto.randomUUID()`, used to match responses |
| Other fields | Depends on command | Such as `hours`, `messages`, `provider`, `session_id`, etc. |

### Response frame (Python → main process)

After command processing completes, Python outputs one line of JSON with:

- `__cmd_response__: true` marker
- `requestId` echoing the ID from the request

If an error occurs, the response contains an `error` field. Common scenarios:

- Command not in the allowlist: returns `error.code = "ipc.err.forbidden"`.
- Parameter validation failure: returns `error.code = "ipc.err.invalidParams"`.
- Command handler throws an exception: returns `"handler error: ..."`.
- stdin line cannot be parsed as JSON: returns `"invalid JSON"`.

### Timeout

The main process `sendToPython()` sets a 10-second timeout; after expiration, the request is removed from `pendingRequests` and the Promise is rejected.

## Streaming and async events

Some operations do not return through `__cmd_response__` but instead push independent event frames:

### AI streaming events

- `type: "ai_token"`: character-by-character token, with `requestId` and `data.token`.
- `type: "ai_done"`: end of stream, with full `text`, `memory`, `error`, and `requestId`.

### Async connection results (v1.5.0+)

- `type: "terminal_connect_result"`: SSH connection result, containing `ok`, `session_id`, or `error`.
- `type: "nas_test_result"`: NAS connectivity test result, containing `ok` and error information.

### Terminal output

Terminal session output frames are not sent through command responses, but pushed directly:

```json
{"session_id": "a1b2c3d4", "data": "ls\r\nfile.txt\r\n"}
```

## State broadcast

The Python main loop calls `_format_state()` every second to build a state frame and output it to stdout. If the current frame string is identical to the previous frame, sending is skipped, but at least one frame is sent every 5 seconds as a heartbeat:

```python
if frame != _last_frame or (now - _last_frame_ts) >= _HEARTBEAT_SECONDS:
    _safe_print(frame, flush=True)
    _last_frame = frame
    _last_frame_ts = now
```

<Note>
  The state broadcast deduplication behavior above comes from the `main.py` main loop implementation in 1.5.1.
</Note>

The state frame contains the following top-level keys:

- `monitor`: CPU, memory, disk, network speed, process list (up to 15 entries).
- `hardware`: CPU, GPU, memory, disk, system information summary.
- `nas`: Online status and load for each NAS device.
- `alerts`: The 5 most recent alert records (with incremental `seq`).

After receiving a state frame, the main process broadcasts it to the renderer process via `mainWindow.webContents.send('state-update', data)`. Alerts are deduplicated by `seq`, and only new alerts that have not been notified are shown.

### stdout lock

The Python backend uses `_stdout_lock = threading.Lock()` to protect `_safe_print`, preventing the main loop's state pushes and command responses/streaming events from interleaving on stdout and causing JSON parsing failures.

## Example JSON Lines

**Request**:

```json
{"cmd": "get_hardware", "requestId": "a1b2-c3d4-e5f6-7890"}
```

**Response**:

```json
{"hardware": {"cpu": {"model": "Intel Core i7", "cores": 8, "threads": 16}, "gpu": {"name": "RTX 3060", "vram_gb": 12}}, "__cmd_response__": true, "requestId": "a1b2-c3d4-e5f6-7890"}
```

**AI token stream**:

```json
{"type": "ai_token", "requestId": "b2c3-d4e5-f6g7-8901", "data": {"token": "Hello", "kind": "content"}}
```

**State frame (excerpt)**:

```json
{"monitor": {"cpu": 8.2, "memory": 42.1, "disk": 55.3, "network_speed": 12.5, "processes": [...]}, "hardware": {"cpu": {"model": "Intel Core i7", "cores": 8, "threads": 16}, "gpu": {"name": "RTX 3060", "vram_gb": 12}}, "nas": {"NAS-01": {"online": true, "cpu": 15.0, "memory": 32.0, "disk": 40.0}}, "alerts": []}
```
