DigitalLab's desktop features are carried by the Electron main process for the UI, and the Python child process for system monitoring, hardware detection, NAS SSH, and AI inference. The two communicate through a JSON Lines protocol over standard input and output, without relying on HTTP.

## Child process startup

The `startPython()` function in `main.js` selects the startup path based on the runtime environment:

**Packaged mode** (`app.isPackaged === true`):

- Uses `resources/backend.exe`, generated by PyInstaller from `backend.spec`.
- Startup arguments: `["--json-mode"]`.
- Working directory: `process.resourcesPath`.

**Development mode**:

- Always uses the system `python` to run the repository's `main.py --json-mode`; it will not start a potentially stale `backend.exe` that may exist in the repository.
- Working directory: `__dirname` (project root).

The following environment variables are set at startup (applied only to this child process):

- `TEMP` / `TMP`: points to `%APPDATA%\digital-lab\tmp` (a dedicated temp directory under the app's userData), used for PyInstaller onefile extraction, without relying on the host machine's temp directory.
- `PYTHONUNBUFFERED=1`: disables stdout buffering to ensure JSON Lines frames are emitted immediately.
- `PYTHONIOENCODING=utf-8`: forces UTF-8 encoding to avoid Chinese decoding errors.

```js
var backendTemp = path.join(app.getPath('userData'), 'tmp');
var backendEnv = {
  ...process.env,
  TEMP: backendTemp,
  TMP: backendTemp,
  PYTHONUNBUFFERED: '1',
  PYTHONIOENCODING: 'utf-8',
};
pythonProcess = spawn(pythonPath, args, {
  cwd: cwd,
  stdio: ['pipe', 'pipe', 'pipe'],
  env: backendEnv,
});
```

## Orphan process cleanup

According to the repository main branch source, `main.py` calls `_kill_orphan_backends()` at the `cmd_json_mode()` entry before anything else, cleaning up PyInstaller backend processes left over from an abnormal exit. It only terminates processes with the same name whose parent process no longer exists, skipping the current process and its ancestor chain.

<Note>
  The orphan cleanup behavior above comes from a cleanup item marked in the current source comments. Implementation details may change between versions.
</Note>

## Automatic restart on crash

The main process maintains a `pythonRetryCount` counter and a `MAX_RETRIES = 3` limit:

- When the Python process exits due to `close` or `error`, the main process increments the counter.
- If the limit is not exceeded, it calls `setTimeout(startPython, 2000)` to restart the process after 2 seconds.
- When a valid state frame containing the `hardware` field is received from the new process, the counter is reset to 0.
- After exceeding 3 attempts, the main process notifies the renderer process via `mainWindow.webContents.send('python-status', { available: false, retriesExhausted: true, ... })`, and the UI presents a failure state.

```js
if (pythonRetryCount > 0 && data.hardware) {
  pythonRetryCount = 0;
}
```

## Single-instance lock and window behavior

- `app.requestSingleInstanceLock()` is called before `app.whenReady()`; if acquisition fails, `app.quit()` is called immediately.
- When a second instance starts, the existing window is restored and focused through the `second-instance` event.
- The close button does not quit the application; instead it hides to the system tray. The tray menu provides **Show Main Window** and **Quit** options.
- Default window size is 1100 x 750, minimum size is 900 x 600.

## Hardware acceleration toggle

Hardware acceleration is disabled by default to support virtual machine environments. On startup, `main.js` reads the `hardware_acceleration` key from the application-level `config.json`:

- If the value is `false` or absent, it calls `app.disableHardwareAcceleration()` and appends Chromium GPU disable switches.
- Users can enable hardware acceleration in the Settings panel; a restart is required after switching.

## Logging and exception handling

`main.js` contains an independent logging subsystem (rewritten in v1.5.0):

- Asynchronously writes to `%APPDATA%\digital-lab\digital-lab.log`.
- Single file limit is 5 MB, keeping 3 rotated files; when the total exceeds 50 MB, old files are deleted directly.
- `uncaughtException` / `unhandledRejection` only write logs and do not call `console.*`, avoiding EPIPE self-amplification.
