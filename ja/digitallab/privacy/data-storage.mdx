本ページでは、DigitalLab が端末上で収集するデータのカテゴリ、保存ディレクトリの構造、ログの内容、および削除方法を説明します。内容は v1.6.0 のコードに基づいて整理しています。収集されたデータは既定で本機のユーザー書き込み可能なディレクトリに書き込まれ、アプリはこれらのファイルを遠隔サーバーへアップロードしません。

## 収集する情報（ハードウェアとパフォーマンス）

DigitalLab は以下の情報を端末上で収集し、ダッシュボードの表示、ローカル分析、AI アシスタントへのコンテキスト提供に使用します。

1. **端末のハードウェア情報**：CPU のモデルと周波数、メモリの容量と種類、GPU のモデルと VRAM、ディスクのモデルと容量、ディスプレイの仕様、ネットワークアダプターの情報、システムのモデルと製造元。
2. **システムのパフォーマンスデータ**：CPU 使用率、メモリ使用率、ディスク使用率、ネットワーク速度、プロセス一覧（PID、名前、CPU とメモリの使用量）。
3. **NAS デバイスのデータ**：ユーザーが設定した NAS デバイスの CPU、メモリ、ディスク、Docker コンテナの状態。アプリは入力したホストアドレスとポートへ SSH 接続して収集し、対象がローカルネットワーク内にあることを限定しません。収集結果は端末上に保存されます。

## データの保存場所

実行データは 2 つのユーザーディレクトリに保存されます。

```text
%APPDATA%\DigitalLab\
├── config.json                # 実行時の公開設定
├── user_config.json           # 機密設定。認証情報の値は DPAPI 暗号文（dpapi:v1:）
├── logs\
│   ├── cache\
│   │   └── hardware.json      # ハードウェア情報のキャッシュ
│   └── monitor\
│       ├── monitor.db         # パフォーマンススナップショットデータベース（SQLite）
│       ├── daemon.log         # 監視ログ（JSON Lines）
│       └── daemon.pid         # 監視デーモンの PID
├── memory\
│   ├── daily.jsonl            # 日次パフォーマンス集計
│   ├── chat_history.jsonl     # AI 会話履歴（既定で有効、上限設定と削除が可能）
│   └── ai_memory.jsonl        # AI 長期メモリ（既定で無効、有効後に生成）
├── snapshots\                 # パフォーマンススナップショット
├── reports\                   # レポート
├── ssh\
│   └── ssh_trust.json         # SSH ホスト信頼ライブラリ（ホストの公開鍵とフィンガープリント、認証情報は含みません）
└── tools\ experiments\ notes\ archive\ interface\   # 予約ディレクトリ

%APPDATA%\digital-lab\
├── config.json                # 画面設定（テーマ、言語、起動スプラッシュ、初回起動ガイドの完了状態、ハードウェアアクセラレーション）
├── digital-lab.log            # Electron 画面ログ
├── digital-lab.log.1 から .3  # 画面ログのローテーションファイル
└── tmp\                       # バックエンド Python プロセスの一時ディレクトリ（TEMP/TMP）
```

プログラムディレクトリ（開発モードではソースコードのルートディレクトリ。パッケージ後はコード上で `backend.exe` のあるディレクトリ、つまりインストール先の `resources\`）には `launchers.json`（クイックランチャー設定）のみを保存します。日次集計、パフォーマンススナップショット、レポートはすべて `%APPDATA%\DigitalLab\` に書き込まれ、プログラムディレクトリには書き込まれません。

<Info>
  **カスタムディレクトリ**：AI メモリのディレクトリは設定からシステムのディレクトリ選択器で変更できます（`ai.memory.dir`）。会話履歴のディレクトリには画面からの変更入口はなく、設定項目 `ai.history.dir` のみで変更できます。両方とも環境変数 `DIGITAL_LAB_AI_MEMORY_DIR` と `DIGITAL_LAB_CHAT_HISTORY_DIR` で上書き可能で、優先順位は環境変数、設定項目、既定のディレクトリです。変更後は選択したディレクトリが準拠となります。メモリディレクトリを変更した場合、旧ファイルは新しいディレクトリにコピーされますが、旧ディレクトリからは削除されません。

  `daily.jsonl` は上記の設定の影響を受けず、常に `%APPDATA%\DigitalLab\memory\` にあります。
</Info>

## ログ

DigitalLab はトラブルシューティングとパフォーマンス分析のため、端末上に実行ログを記録します。

| ファイル | 書き込み元 | 内容 |
| --- | --- | --- |
| `%APPDATA%\DigitalLab\logs\monitor\daemon.log` | Python バックエンド | JSON Lines 形式で、タイムスタンプ、レベル、イベントメッセージ、および関連フィールド（例：プロセス PID、収集回数、指標しきい値、NAS デバイス名とホストアドレス）を記録 |
| `%APPDATA%\digital-lab\digital-lab.log` | Electron メインプロセス | ウィンドウのライフサイクル、ページ読み込み失敗、メインプロセスの未捕捉例外のメッセージとスタック、I/O エラーの要約、バックエンドの一時ディレクトリパス、バックエンドプロセスの終了コード、およびバックエンドエラー出力の抽出タグと長さのカウント（原文は含みません） |
| `%APPDATA%\DigitalLab\logs\cache\hardware.json` | Python バックエンド | ハードウェア情報のキャッシュ。毎回の起動時に再収集しないため（ログではなく、`logs\` 配下にあります） |

画面ログは 1 ファイルあたり上限 5 MB で、超過するとローテーションされ `digital-lab.log.1` から `.3` を保持します。起動時に残留ファイルが大きすぎると検出された場合、末尾 256 KB のみを保持します。

ログのプライバシー境界：

- ログには AI の対話内容と AI リクエストのコンテキストは含まれず、端末上にのみ書き込まれ、いかなるサーバーへもアップロードされず、ユーザー行動の分析にも使用されません。
- ログシステムは汎用的なフィールドマスキングを行いません。監視ログには NAS デバイス名とホストアドレスが含まれる可能性があります。画面ログの例外メッセージ、スタック、パス（Windows ユーザー名を含む可能性があります）はそのまま書き込まれます。
- バックエンド（Python）エラー出力（stderr）の原文は画面ログに書き込まれません。エラー出力を受信するたびに、画面ログには `Python stderr: kind=<タグ> bytes=<長さ>` の 1 行のみ記録されます。
  - タグはその出力の最初のコロンまでのテキストから取得し、英字、アンダースコア、スペースのみを保持し、最大 40 文字です。そのため、エラー出力の先頭の少量の英単語が含まれる可能性があります。
  - 長さは前後の空白を除去した文字列の長さ（`text.length`、UTF-16 コード単位でカウント）です。フィールド名は `bytes` ですが、実際のバイト数ではありません。
  - バックエンドプロセス終了時には終了コードのみを記録します。コード中に予約されている「stderr tail」バッファは書き込まれたことがないため、エラー出力の末尾の内容は記録されません。
- AI リクエストが失敗した場合、画面に返されるエラー概要は URL を除去し、`authorization`、`bearer`、`api_key`、`password`、`token` などのキーと値のパターンを `<redacted>` に置換し、160 文字で切り捨てられます。これはエラー表示のマスキングであり、ログシステムのマスキングではありません。

`%APPDATA%\DigitalLab\logs\` ディレクトリと `%APPDATA%\digital-lab\` 配下の `digital-lab.log*` ファイルを削除するとログを消去できます。ログを共有する前に内容を確認してください。

## データの削除方法

### アプリ内からの削除

- **会話履歴**：設定 → AI アシスタント → 会話履歴。保存のオン/オフ（新しい記録の書き込み停止）、保存件数の上限（超えた分は古い順に削除）、すべて消去（取り消し不可）ができます。現在の画面には 1 件ずつの削除入口はありません（バックエンドには対応するインターフェースがあります）。
- **AI メモリ**：設定 → AI アシスタント → AI メモリ。メモリのオン/オフ、項目の表示、1 件ずつの削除、すべて消去が可能です。さらに「重複を整理」で重複した項目を統合できます（同じ内容は最も古い 1 件を保持）。メモリの保存先を変更した場合は、旧ディレクトリのファイルも削除してください。
- **認証情報**：設定画面から保存済みの API Key と NAS パスワードを消去できます。
- **その他の設定**（AI プロバイダー、監視しきい値、デバイス一覧、テーマ、言語など）：項目ごとに変更するか、以下に示す方法でデータディレクトリを手動で削除してください。

### 手動での削除

- `%APPDATA%\DigitalLab\`：公開設定と機密設定、監視ログとスナップショットデータベース、ハードウェアキャッシュ、日次集計、パフォーマンススナップショット、レポート、SSH ホスト信頼ライブラリ、AI 会話履歴、AI メモリ
- `%APPDATA%\digital-lab\`：画面設定、画面ログと一時ディレクトリ
- プログラムディレクトリ内の `launchers.json`：クイックランチャー設定
- 会話履歴または AI メモリのディレクトリを変更した場合は、対応するディレクトリ内のファイルも削除してください

アプリをアンインストールしても上記 2 つの `%APPDATA%` ディレクトリは自動削除されません。手動で削除する必要があります。

<Warning>
  `launchers.json` のアンインストール時の消去動作はまだ検証されていません。これはアプリの実行時にプログラムディレクトリへ書き込まれるファイルであり、インストーラーが配布するファイルではありません。アンインストールプログラムがこれを削除するかどうかは現在実測されていません。アンインストール後は元のインストールディレクトリを確認し、残留があれば手動で削除してください。また、プログラムディレクトリはマシン単位でのインストールまたは Microsoft Store のインストール時には書き込み不可となる可能性があり、クイックランチャー設定が正常に保存できるかどうかもまだ検証されていません。
</Warning>
