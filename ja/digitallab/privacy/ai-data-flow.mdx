本ページでは、AI アシスタントが生成するデータのカテゴリ、保存方法、リクエストの構成、およびデータが端末外へ出る条件について詳細に説明します。内容は v1.6.0 のコードに基づいて整理しています。

<Note>
  AI アシスタントは現在、対話モードであり、**エージェントのツール呼び出し機能は含みません**。リクエストにはツール定義が含まれず、モデルは端末のツールを呼び出せません。リポジトリ内の `core/agent_tools.py` は現在、モデルに開放されていません。
</Note>

## 収集する情報（AI 関連）

DigitalLab は端末上で以下の AI 関連の情報を収集または生成します。

### AI 対話履歴

ユーザーと AI アシスタントの対話内容（AI 機能を使用した場合にのみ生成）。既定では本機のファイル `%APPDATA%\DigitalLab\memory\chat_history.jsonl` に保存され、再起動後に復元されます。設定パネルの「会話履歴」で保存のオン/オフ、保存件数の上限（20 ～ 5000、既定は 200、超えた分は古い順に削除）、または一括消去ができます。

- 「会話履歴を保存」をオフにすると、新しいメッセージをそのローカルファイルへ書き込まなくなるだけで、既存の記録は削除されません（手動で消去するかファイルを削除してください）。
- 「会話履歴を保存」をオフにしても AI リクエストは停止しません。今回送信するメッセージとセッション内の既存の対話内容は、今回のリクエストとして選択した AI サービスへ送信されます。
- 対話履歴ファイルそのものが丸ごといかなるサーバーへもアップロードされることはありません。

### AI メモリ（オプション、既定はオフ）

設定でメモリを有効にした場合に限り、対話で明示的に述べ、長期的に記憶する価値がある好み（呼称、デバイス名、使用習慣など）が `%APPDATA%\DigitalLab\memory\ai_memory.jsonl` に永続保存されます。

- **書き込み**：モデルの返信にメモリマークが付いた内容が抽出され、1 回の返信から最大 3 件、1 件あたり最大 500 文字までです。メモリマークは表示される返信から常に除去されますが、メモリを有効にした場合のみファイルへ書き込まれます。
- **注入**：メモリを有効にすると、毎回のリクエストに最近のメモリ 10 件の内容が注入され、1 件あたり 200 文字に切り捨てられます。
- **端末外へ出る条件**：メモリを有効にしてリモートモデルを使用する場合、注入されたメモリ内容はそのサービスへリクエストとともに送信されます。
- **メモリを無効にした後**：新しいメモリは書き込まれず、保存済みのメモリファイルは読み出しや対話への注入は行われませんが、ファイル自体は端末上に残ります。設定から削除または消去してください。

### AI リクエストのコンテキスト（AI 機能を使用した場合にのみ生成）

バックエンドが毎回組み立てるメッセージ一覧（JSON リクエスト本文の `messages`、つまりモデルが参照できるコンテキスト）は 4 つの部分から成ります。

1. **静的プロンプト**：役割設定、利用ルール、出力形式の制約。メモリ有効時にはメモリ指示も含みます。
2. **メモリ内容**：メモリ有効時のみ。最近 10 件。時刻と識別子で決定的に並べられます。
3. **リアルタイムのシステム状態の要約**：CPU/メモリ/ディスク使用率、CPU/GPU/メモリ/ディスクの型番と容量、設定済み NAS デバイスの名前、オンライン状態、CPU/メモリ/ディスク使用率と温度。
4. **対話内容**：今回送信するメッセージとセッション内の既存の対話。バックエンドは直近 16 件のみ保持します。

以下の情報は**モデルのコンテキストに入りません**：NAS のホストアドレスとログイン認証情報、プロセス一覧全体とコマンドライン、ログの内容、AI メモリの識別子/種類/タグ/取得元の各フィールド、API Key。

**AI メモリと対話履歴は互いに独立した機能です**：メモリのオン/オフは長期メモリの読み出し・注入・永続化を制御し、既定はオフです。対話履歴の保存オン/オフはローカルの会話記録の書き込みを制御し、既定はオンです。一方をオフにしても他方はオフにならず、AI リクエストも停止しません。

## 1 回のリクエストに含まれるもの

1 回の AI リクエストは HTTP リクエストヘッダーと JSON リクエスト本文の 2 つの部分から成り、それぞれの内容は異なります。

| 部分 | 内容 | モデルが参照できるか |
| --- | --- | --- |
| HTTP リクエストヘッダー | `Content-Type: application/json`。クラウドモデルの場合は `Authorization: Bearer <API Key>` も追加 | いいえ。サービス側の認証専用です |
| JSON リクエスト本文 | `model`（モデル名）、`messages`（上記 4 つのコンテキスト）、`stream: true` | `messages` がモデルのコンテキストです |

API Key は毎回のクラウドリクエストとともに設定したエンドポイントへ送信されますが、`Authorization` リクエストヘッダーにのみ含まれ、JSON リクエスト本文、プロンプト、システムメッセージ、対話内容には書き込まれません。Ollama へ送信するリクエストには `Authorization` リクエストヘッダーは付きません。

## モデルの選択とデータの行き先

| 項目 | Ollama | クラウドモデル（OpenAI 互換 API） |
| --- | --- | --- |
| 既定アドレス | `http://localhost:11434`（設定で変更可能） | `https://api.deepseek.com`（設定で変更可能） |
| 既定モデル名 | `llama3` | `deepseek-chat` |
| リクエストパス | `{base_url}/api/chat` | `{base_url}/v1/chat/completions` |
| データが端末外へ出るか | 本機アドレス使用時はいいえ。他のホストに変更すると、そのホストへ送信されます | はい。設定したサービスエンドポイントへ送信されます |
| API Key | 送信しません | 必須。`Authorization: Bearer` リクエストヘッダーとして送信します |
| AI 対話履歴の保存 | 本機の `chat_history.jsonl` | 同左。履歴は常にローカルに保存されます |
| AI メモリの保存 | 本機の `ai_memory.jsonl` | 同左。メモリは常にローカルに保存されます |
| モデルのコンテキスト範囲 | 静的プロンプト、メモリ（有効時）、リアルタイムのシステム状態、直近 16 件の対話 | 同左 |

両方のモデルのアドレスは同一の [AI エンドポイントの通信ポリシー](/ja/digitallab/privacy/sensitive-information#ai-エンドポイントの通信ポリシー) の制約を受けます。

- リモート HTTPS は許可され、既定の TLS 証明書検証を使用します。`ai.ca_bundle` でカスタム CA を指定でき、ファイルが存在しないか読み取れない場合はリクエストが失敗します。
- loopback HTTP は許可されます。
- プライベートネットワークと Tailscale アドレスの HTTP は、`ai.allow_insecure_http` で `ip[:port]` の正確な許可が必要です。
- ドメイン、パブリック IP、link-local、クラウドメタデータアドレスの HTTP はすべて拒否されます。
- リクエストは HTTP リダイレクトに追随しません。

## リクエストのフロー

<Steps>
  <Step title="ユーザー入力">
    AI アシスタントパネルにメッセージを入力し、送信します。
  </Step>
  <Step title="コンテキストの組み立て">
    バックエンドがモデルのコンテキストを組み立てます。静的プロンプト、メモリ内容（有効時）、リアルタイムのシステム状態の要約、直近 16 件の対話です。
  </Step>
  <Step title="エンドポイントのチェック">
    バックエンドは AI エンドポイントの通信ポリシーに従って設定されたアドレスをチェックし、ポリシーに合致しないリクエストは即座に失敗し、送信されません。
  </Step>
  <Step title="リクエストの送信">
    Ollama を使用する場合、リクエストは設定した Ollama アドレスへ送信されます（既定は本機の `localhost:11434` で、データは端末外へ出ません）。クラウドモデルを使用する場合、リクエストは設定した `base_url` へ送信され、API Key は `Authorization` リクエストヘッダーに入り、データは当該サービスで処理されます。
  </Step>
  <Step title="ローカルへの記録">
    対話内容は「会話履歴を保存」のオン/オフに応じて、ローカルの `chat_history.jsonl` への書き込みが決定されます。メモリを有効にすると、返信のメモリマークが抽出され `ai_memory.jsonl` へ書き込まれます。
  </Step>
</Steps>
