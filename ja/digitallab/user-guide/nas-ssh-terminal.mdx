DigitalLab には xterm.js ベースの SSH ターミナルが組み込まれており、設定した NAS デバイスに接続してリモートコマンドの実行や管理操作を行えます。v1.6.0 から、ターミナルは独立した "DigitalLab Terminal" ウィンドウで実行され、ターミナルパネル自体は接続可能なデバイスの一覧表示のみを担当します。

<Warning>
  **SSH ターミナル** は現在 **テスト段階** にあり、パネルに初めて入るときに通知が表示されます。一部の機能は安定していない可能性があるため、問題が発生した場合はフィードバックの入口から報告してください。
</Warning>

## NAS デバイスの追加

ターミナルを使用する前に、**設定パネル** の **NAS デバイス** タブでデバイスを追加する必要があります。

1. **設定パネル** を開く
2. **NAS デバイス** タブに切り替える
3. **\+ デバイスを追加** をクリック
4. デバイス名、ホストアドレス、SSH ポート、ユーザー名、パスワードを入力
5. 設定を保存

デバイスを追加すると自動的に接続を試みます。デバイスを編集するときに **接続テスト** ボタンをクリックして、認証情報が正しいか確認することもできます。NAS では SSH サービスを有効にしておく必要があります。

## SSH ホストの信頼

DigitalLab は、認証情報を送信する前に NAS の SSH ホストキーを検証します。信頼関係は `ホスト:ポート` ごとに記録され、ホストアドレスまたはポートを変更すると新しいホストと見なされます。

<Steps>
  <Step title="フィンガープリントの確認">
    初めて未信頼のホストに接続すると、接続は拒否され、設定パネルにそのホストの SHA256 フィンガープリントが表示されます。
  </Step>
  <Step title="NAS 上で独立して照合">
    NAS のコンソールで以下のコマンドを実行し、出力のフィンガープリントが設定パネルに表示されたものと一致することを確認してください。

    ```bash
    ssh-keygen -lf /etc/ssh/ssh_host_*_key.pub
    ```
  </Step>
  <Step title="信頼の確認">
    一致を確認したら、**確認しました。このホストを信頼する** をクリックします。フィンガープリントが `%APPDATA%\DigitalLab\ssh\ssh_trust.json` に保存され、その後接続テストをやり直します。
  </Step>
</Steps>

- 未信頼またはフィンガープリントが一致しないホストには **認証情報が送信されません**
- 信頼済みのホストでフィンガープリントが変化した場合、接続は直ちに拒否され、再照合と再信頼が必要になります
- 信頼ファイルにはホストの公開鍵、アルゴリズム、フィンガープリント、信頼時刻のみ保存され、認証情報や秘密鍵は保存されません

## ターミナルを開く

<Steps>
  <Step title="ターミナルパネルに入る">
    サイドバーの **ターミナル** をクリックします。パネルには、現在オンラインで非 Mock の NAS デバイスが一覧表示されます。
  </Step>
  <Step title="デバイスを選択">
    デバイス項目のボタンをクリックします。アプリはシステムネイティブの確認ダイアログ「打开 SSH 终端？」（SSH ターミナルを開きますか？。v1.6.0 ではこのダイアログは中国語で表示されます）を表示し、デバイス名、対象の `ホスト:ポート` を示し、未信頼のホストには認証情報が送信されないこと、ターミナルは独立ウィンドウで実行されることを通知します。
  </Step>
  <Step title="独立ウィンドウで操作">
    確認後、ターミナルは "DigitalLab Terminal" ウィンドウで開きます（デフォルト 900 x 600、最小 600 x 400）。ウィンドウのステータスバーには `Connected` または `Session closed` が表示されます。
  </Step>
</Steps>

### セッションの動作

- ターミナルウィンドウが既に開いているか開いている途中の場合、再度開くことは拒否されます
- ターミナルウィンドウを閉じたり、ウィンドウの読み込みに失敗したり、レンダリングプロセスがクラッシュした場合、バックエンドは対応する SSH セッションを閉じます
- バックエンドはセッションの出力を 256 KB までバッファリングしており、ターミナルウィンドウがセッションに接続するとこの出力が再生されます
- 1 回の入力は最大 8192 文字までで、頻度制限があります
- ターミナルウィンドウのコンテンツセキュリティポリシー（CSP）により、レンダリングプロセスからのネットワーク接続は禁止されています

<Warning>
  SSH セッションは **自動再接続をサポートしていません**。ウィンドウを閉じたり、ネットワークが切断されたり、バックエンドが再起動したりしてセッションが終了した場合、ターミナルパネルに戻ってターミナルを再度開く必要があります。
</Warning>

### ターミナルのテーマ

ターミナルウィンドウは、**ダークテーマ** と **ライトテーマ** の両方で CMD スタイルのダーク背景を保持します。

## 既知の制限

- **Linux ベースの NAS のみサポート**: SSH コマンドでデータを取得するため、他のプラットフォームの NAS は現在サポートされていません
- **自動再接続をサポートしない**: セッション終了後に手動で再度開く必要があります
- **SSH サービスを有効にする必要がある**: 対象の NAS で SSH サービスが起動しており、認証情報が正しいことを確認してください
- **初回接続時にホストを信頼する必要がある**: フィンガープリントの照合が完了するまで認証は完了しません

## セキュリティに関する注意

NAS のパスワードは、Windows DPAPI の現在ユーザー範囲の暗号文（`dpapi:v1:`）として `%APPDATA%\DigitalLab\user_config.json` に保存され、設定画面では「設定済み」の状態のみが表示されます。ホストアドレス、ユーザー名などの他のデバイスフィールドは読み取り可能な JSON のままですが、このファイルは引き続き機密ファイルとして管理し、他人と共有しないでください。NAS の認証情報は AI リクエストとともに送信されません。

認証情報の保存の詳細については、[機密情報の取り扱い](/ja/digitallab/privacy/sensitive-information) を参照してください。
