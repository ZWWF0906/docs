AI アシスタントは DigitalLab のインテリジェントな対話パネルです。ローカルの Ollama モデルとクラウドの OpenAI 互換 API をサポートし、リアルタイムのシステム状態に基づいて、ハードウェア、パフォーマンス、NAS に関する質問に回答します。

<Warning>
  **AI アシスタント** は現在 **テスト段階** にあり、パネルに初めて入ると通知が表示されます。現在は対話モードのみをサポートしており、Agent のツール呼び出し機能は含まれていません。
</Warning>

## モデルプロバイダーの切り替え

AI アシスタントは 2 種類のプロバイダーをサポートしており、パネル上部で切り替えられます。

- **Ollama ローカル**: 本機の `localhost:11434` に接続します。データは本機の外に出ません
- **クラウド API**: 設定した OpenAI 互換のサービスエンドポイント（DeepSeek など）に接続します

プロバイダーを切り替えると自動的に設定に保存され、次回の起動時も前回の選択が保持されます。プロバイダー、サービスアドレス、API Key を変更すると、アプリはシステムネイティブの確認ダイアログを表示します。

### サービスエンドポイントの要件

- **リモートエンドポイントには HTTPS が必須** です。システム既定の TLS 証明書検証を使用し、アプリには検証を無効にするスイッチはありません
- **ローカルの loopback アドレス**（`http://localhost:11434` など）では HTTP を使用できます
- **プライベートネットワークまたは Tailscale アドレスへの HTTP**: 設定項目 `ai.allow_insecure_http` に IP リテラルで `ip[:port]` を正確に登録した場合にのみ許可されます。ドメイン名を使った HTTP アドレスや、パブリック IP の HTTP アドレスは拒否されます。設定パネルには現在この項目の入力欄はありません
- **カスタム CA**: 設定項目 `ai.ca_bundle` で CA Bundle ファイルを指定できます。明示的に設定したファイルが存在しない、または読み取れない場合、リクエストはそのまま失敗し、システムの信頼ストアにはフォールバックしません
- リクエストはリダイレクトに追従しません

詳しくは [機密情報の取り扱い](/ja/digitallab/privacy/sensitive-information) を参照してください。

## ストリーミング対話

AI アシスタントは **ストリーミング出力** を採用しており、モデルが生成した内容はトークン単位（token-by-token）で対話欄に順次表示されます。完全な回答を待つ必要はありません。v1.6.0 から、ストリーミングレスポンスには 1 行の長さ、合計サイズ、思考（reasoning）チャネルの上限が設けられています。

メッセージを送信すると、AI の回答には現在のシステム状態がコンテキストとして自動的に注入されます。内容は次のとおりです。

- CPU、メモリ、ディスクのリアルタイム使用率
- 本機のハードウェアモデルと容量
- 設定済み NAS デバイスのオンライン状態と負荷指標

「CPU 使用率はどのくらい？」「NAS のメモリはまだ足りている？」のように直接質問すると、AI はリアルタイムのデータに基づいて回答します。

## 推奨モデル

ローカルの Ollama を使用する場合は、中国語の能力が高いモデルを推奨します。

- `qwen2.5:7b-instruct-q4_K_M`

## インターフェース言語

v1.4.0 から、AI アシスタントは選択したインターフェース言語で回答します。**設定パネル** で簡体字中国語、英語、日本語のいずれかに切り替えると、AI の回答もその言語に合わせて変わります。

## 会話履歴

v1.5.0 から、会話履歴の保存は既定で有効になっており、`%APPDATA%\DigitalLab\memory\chat_history.jsonl` に保存されます。

- アプリを再起動すると、前回の対話が自動的に復元されます
- **設定パネル** で保存の無効化、保存件数の上限の調整、履歴の一括消去ができます

<Note>
  「会話履歴を保存」をオフにすると、新しい記録の書き込みが止まるだけで、既存のファイルは削除されません。送信するメッセージは、引き続きリクエストとともに AI プロバイダーに送信されます。
</Note>

## AI メモリ

AI メモリは本機に保存される長期記憶で、**既定では無効** です。有効にすると、AI は対話の中であなたが明確に示した長期的な好み（呼び方、デバイス名、使用習慣など）を記憶し、以降の対話で参照します。

- **保存場所**: 既定は `%APPDATA%\DigitalLab\memory\ai_memory.jsonl` です。設定からネイティブのディレクトリ選択ダイアログでディレクトリを変更できます
- **エントリ構造**: 各メモリには内容、時刻、カテゴリ、タグ、ソースなどのフィールドが含まれます。モデルに送信されるのはメモリの内容そのものだけで、ID、カテゴリ、タグ、ソースのフィールドはリクエストに含まれません
- **注入方法**: 有効にすると、直近のいくつかのメモリがリクエストとともに注入されます。クラウドモデルを使用する場合、これらのメモリ内容はそのサービス提供元に送信されます
- **無効にした後**: 新しいメモリの書き込みも、読み取りや注入も行われなくなりますが、既存のファイルは本機に残ります

**設定パネル** では、メモリエントリの閲覧、個別削除、全消去、重複の整理（同じ内容は最も古い 1 件を残す）ができます。

<Note>
  **バージョンの変遷**: v1.2.0 でローカルメモリを導入し、v1.5.0 でエントリに id、タグ、ソースのフィールドを追加しました。README の Roadmap では Personal Digital Memory を v1.6.0 で完了としています。現在の実装はローカルの JSONL ストレージとキーワード検索で、ベクトルデータベースは使用していません。
</Note>

<Info>
  AI メモリと会話履歴は互いに独立した 2 つの機能です。一方を無効にしてももう一方は無効にならず、AI リクエストも停止しません。
</Info>

## クイックデプロイボタン

AI アシスタントパネルの上部には **クイックデプロイ** ボタンがあります。これは v1.3.0 で追加されたプレースホルダー機能です。クリックしても「この機能は開発中です。今しばらくお待ちください」という通知が表示されるだけで、機能はまだ実装されていません。

## Agent 自動化機能

<Warning>
  **Agent 自動化機能** はロードマップ上の計画項目で、現在のバージョンでは **まだ実装されていません**。AI アシスタントは対話による Q&A のみをサポートしており、ツール呼び出し、コマンドの自動実行、自動デプロイの機能はありません。
</Warning>

リポジトリ内の `core/agent_tools.py` は読み取り専用の Agent ツール用の基盤で、現在はモデルに公開されていません（`MODEL_EXPOSURE_ENABLED = False`）。これは AI アシスタントがツール呼び出し機能を備えていることを意味しません。

## プライバシーに関する説明

クラウドモデルを使用する場合、次のデータがリクエストとともに、設定した API エンドポイントに送信されます。

- 対話内容（直近 16 件）
- 静的プロンプトとリアルタイムのシステム状態の要約
- 有効にした AI メモリの内容

API Key は `Authorization` リクエストヘッダーとしてのみ送信され、プロンプトや対話本文には書き込まれません。NAS のホストアドレスと認証情報、完全なプロセス一覧、ログの内容はリクエストに含まれません。ローカルの Ollama を使用する場合、上記のデータは本機でのみ処理されます。

AI データフローの詳細については、[AI データフロー](/ja/digitallab/privacy/ai-data-flow) を参照してください。
