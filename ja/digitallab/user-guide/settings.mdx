**設定パネル** は DigitalLab の設定センターで、NAS デバイス、AI 設定、収集設定、ソフトウェア、このアプリについての 5 つのタブに分かれています。左側のタブで切り替えられます。

## NAS デバイス

**NAS デバイス** タブでは、リモートデバイスを管理します。

- **デバイスを追加**: 名前、ホストアドレス、SSH ポート、ユーザー名、パスワードを入力します
- **デバイスを編集**: デバイスカードの **編集** ボタンをクリックして情報を変更します。保存済みのパスワードは「設定済み（空欄なら変更しません）」と表示され、新しい値を入力したときだけ送信されます。**保存済みパスワードを消去** をクリックすると明示的に削除できます
- **デバイスを削除**: **削除** ボタンをクリックして設定を削除します
- **接続テスト**: デバイスの編集時に、SSH 認証情報が正しいかを確認します
- **すべて保存**: デバイス一覧を設定に書き戻し、バックエンドに NAS 監視の再起動を通知します

### SSH ホストの信頼

未信頼のホストや、フィンガープリントが変わったホストに接続すると、設定パネルにそのホストのフィンガープリントが表示され、NAS のコンソールで `ssh-keygen -lf /etc/ssh/ssh_host_*_key.pub` を実行して照合するよう求められます。一致を確認したら **確認しました。このホストを信頼する** をクリックします。詳しくは [NAS と SSH ターミナル](/ja/digitallab/user-guide/nas-ssh-terminal) を参照してください。

### サンプル NAS

このスイッチは、サンプルの NAS データを有効にするかどうかを制御します。開発やテストの場面で使用します。

## AI 設定

**AI 設定** タブでは、AI アシスタントのプロバイダーと詳細オプションを管理します。

### AI プロバイダー

既定で使用する AI プロバイダーとして、**Ollama ローカル** または **クラウド API** を選択します。

### Ollama ローカルの設定

- **アドレス**: Ollama サービスのエンドポイント（`http://localhost:11434` など）
- **モデル**: 使用するモデル名。入力欄のプレースホルダーの例は `llama3` で、README では `qwen2.5:7b-instruct-q4_K_M` を推奨しています

### クラウド API の設定

- **API Key**: OpenAI 互換 API の認証に使用します。保存済みの Key は「設定済み（新しい値を入力すると置き換えます）」とだけ表示され、平文は表示されません。**キーを消去** をクリックすると削除できます
- **アドレス**: API のベース URL。リモートアドレスには `https` が必須で、ローカルの loopback アドレスでは `http` を使用できます
- **モデル**: 呼び出すモデル名（`gpt-4o`、`deepseek-chat` など）

### 機密性の高い変更の確認

AI プロバイダー、サービスアドレス、API Key、メモリの保存ディレクトリなど機密性の高い設定を変更すると、アプリはシステムネイティブの確認ダイアログを表示し、確認後にのみ保存します。プライベートネットワークの HTTP 例外（`ai.allow_insecure_http`）とカスタム CA Bundle（`ai.ca_bundle`）は設定ファイルレベルのオプションで、設定パネルには現在対応する入力欄がありません。[設定とストレージ](/ja/digitallab/architecture/configuration-storage) を参照してください。

### AI メモリ

- **AI メモリを有効にする**: 有効にすると、確認済みの長期的な好みを AI が記憶します
- **保存ディレクトリ**: 読み取り専用の入力欄です。**ディレクトリを選択** ボタンでシステムネイティブのディレクトリ選択ダイアログを開きます。空欄の場合は既定のディレクトリ `%APPDATA%\DigitalLab\memory` を使用します。ディレクトリを変更して保存すると、古いメモリファイルは新しいディレクトリにコピーされ、古いファイルも残ります。移行に失敗した場合は元のディレクトリが維持され、移行先の既存ファイルは上書きされません。UNC パス、デバイスパス、パストラバーサル、シンボリックリンクによるリダイレクトは拒否されます
- **メモリを表示**: 保存済みのメモリエントリを閲覧します
- **メモリを消去**: すべてのメモリエントリを削除します
- **重複を整理**: 内容が重複するメモリエントリを統合し、同じ内容は最も古い 1 件だけを残します

### 会話履歴

- **会話履歴を保存**: 既定で有効です。対話をローカルファイルに書き込むかどうかを制御します
- **保存件数の上限**: 上限を超えると古いものから自動的に削除されます。既定は 200 件です
- **履歴を消去**: 保存済みの対話記録を一括で削除します

**AI 設定を保存** をクリックすると、設定が書き戻され、AI アシスタントパネルにプロバイダーの更新が通知されます。

## 収集設定

**収集設定** タブでは、監視パラメータを調整します。

### 収集パラメータ

| 設定項目 | 既定値 | 範囲 |
| --- | --- | --- |
| ローカル収集間隔 | 1 秒 | 1～60 秒 |
| NAS 収集間隔 | 15 秒 | 5～300 秒 |

### 監視しきい値

| 設定項目 | 既定値 | 範囲 |
| --- | --- | --- |
| CPU アラート | 80% | 10%～100% |
| メモリアラート | 85% | 10%～100% |
| ディスクアラート | 90% | 10%～100% |

指標がしきい値を継続して超えると、デスクトップ通知が表示されます。値がしきい値を下回るまで、同じ通知は繰り返されません。

**収集設定を保存** をクリックすると、変更はすぐに反映されます。

<Note>
  設定ファイルには、さらに高度なオプション（ログレベル、ログの保持日数、Web Dashboard のポートなど）があります。設定項目の詳しい説明と二層構造の設定ストレージについては、[設定とストレージ](/ja/digitallab/architecture/configuration-storage) を参照してください。
</Note>

## ソフトウェア

**ソフトウェア** タブでは、インターフェースとシステムレベルのオプションを調整します。

### ハードウェアアクセラレーション

Chromium のハードウェアアクセラレーションを有効にするかどうかを制御します。仮想マシンでの互換性を高めるため **既定では無効** です。有効にするとグラフィックス描画の性能が向上しますが、反映にはアプリの再起動が必要です。

### テーマ

- **ダーク（既定）**: DigitalLab の既定のダークテーマ
- **ライト**: Emerald デザインシステムに基づくライトテーマ。300ms のスムーズな切り替えに対応しています

<Note>
  どちらのテーマを選んでも、**ターミナルパネル** は常にダークな CMD スタイルを保ち、長時間の操作でも見やすさを確保します。
</Note>

### スプラッシュアニメーション

起動時にスプラッシュアニメーションを再生するかどうかを制御します。無効にすると、起動時に直接メイン画面が表示されます。**次回の起動から有効** です。

### 言語

3 つのインターフェース言語をサポートしています。

- 简体中文
- English
- 日本語

切り替えるとすぐに反映され、自動的に保存されます。再起動後も保持されます。

### 初回起動ガイド

**セットアップを再実行** をクリックすると、3 ステップの初回起動ガイド（言語の選択、NAS デバイスの設定、接続の確認）をもう一度実行できます。

## このアプリについて

**このアプリについて** タブでは、次の情報を確認できます。

- アプリのバージョン番号
- 機能一覧
- 作者とライセンス情報（「DigitalLab は ISC ライセンスのオープンソースソフトウェアです」）
- **フィードバック** の入口: メールまたは GitHub Issues で、フィードバックの送信や不適切な内容の報告ができます

## フィードバックの入口

DigitalLab には、フィードバックと報告のための統一された入口があり、次の方法をサポートしています。

- **メールでフィードバック**: システム既定のメールクライアントを起動します。宛先は `ZWWF0906@outlook.com` です
- **GitHub でフィードバック**: [GitHub Issues](https://github.com/ZWWF0906/Digital-Lab/issues/new) の作成ページを開きます
