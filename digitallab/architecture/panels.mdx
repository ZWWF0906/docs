DigitalLab 的前端由五个功能面板组成，统一注册在 `panels/index.js` 中，由 `dashboard.html` 通过 `renderer.js` 按需加载与切换。面板按 README 的"面板按需加载"原则运行：核心功能无需网络，面板仅在用户切换时初始化。

## 面板注册表

`panels/index.js` 导出 `PANELS` 数组，每个面板包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 面板标识，如 `dashboard`、`terminal`、`ai` |
| `nameKey` | i18n 键名，如 `nav.dashboard` |
| `icon` | 侧栏显示的 Unicode 图标字符 |
| `init` | 面板初始化函数 `(container, api) => hooks` |

当前五个面板：

- `dashboard`（仪表盘）
- `device-center`（设备中心）
- `terminal`（SSH 终端）
- `ai`（AI 助手）
- `settings`（设置面板）

相关文件还包括 `panels/index.js`（注册表）、`panels/safe-dom.js`（安全 DOM 工具）。`safe-dom.js` 为各面板提供 HTML 文本/属性转义、URL 校验与元素创建辅助函数，`dashboard.js`、`device-center.js`、`ai-assistant.js` 均从中导入相关函数。

## 国际化面板名

面板名称不硬编码，而是通过 `i18n.js` 与 `locales/` 下的语言文件动态解析：

- `panels/index.js` 中的 `getPanelName(id)` 调用 `window.DigitalLabI18n.t(p.nameKey)`。
- 语言切换后，`dashboard.html` 监听 `language-changed` 事件并重建侧栏，从而刷新面板名称。

支持三种界面语言：简体中文（`zh-CN`）、英文（`en-US`）、日文（`ja-JP`），对应 `locales/zh-CN.js`、`locales/en-US.js`、`locales/ja-JP.js`。

## 加载与生命周期

`renderer.js`（由 `dashboard.html` 加载）负责面板切换逻辑：

1. **初始加载**：默认激活 `dashboard` 面板。
2. **切换面板**：
   - 更新侧栏高亮。
   - 若目标面板是保活面板（`KEEP_ALIVE_PANELS = { terminal: true }`），且已有缓存容器，则将其从隐藏容器移回主区并调用 `attach()`，不重新初始化。
   - 其他面板切换时销毁旧容器并重新调用 `init()`。
3. **保活机制**：v1.5.0 起 `terminal` 面板启用保活，切换出去时调用 `detach()` 并移入 `#panel-hold` 隐藏容器。

<Note>
  从 v1.6.0 起，主窗口中的 `terminal` 面板不再持有 xterm 实例或 SSH 输入能力，只列出在线 NAS 设备并请求主进程打开独立的 Terminal 窗口。真正的 xterm 与输入处理位于 `terminal.html`、`preload-terminal.js` 与 `renderer-terminal.js` 中；后端为会话保留 256 KB 输出缓冲，终端窗口连接时回放。
</Note>

## 状态消费

所有面板通过 `window.digitalLab.onStateUpdate(callback)` 订阅全局状态广播。回调接收的状态帧结构与 /digitallab/architecture/jsonl-ipc 中的状态帧一致。

以 `dashboard.js` 为例：

- 收到 `state-update` 后读取 `state.monitor.cpu`、`state.hardware` 等字段更新卡片数值。
- 进程表读取 `state.monitor.processes` 并渲染前 15 条。
- 通过 `api.reloadConfig()` 触发配置重载。

以 `device-center.js` 为例：

- 通过 `api.onStateUpdate` 聚合本机与 NAS 设备状态，渲染在线/离线设备卡片与资源指标。

以 `terminal.js` 为例：

- 通过 `api.onStateUpdate` 获取在线 NAS 设备列表（排除 Mock 设备）。
- 通过 `api.terminalOpen(name, 80, 24)` 请求主进程弹出原生确认框并打开独立 Terminal 窗口。

以 `ai-assistant.js` 为例：

- 通过 `api.onAiToken` / `api.onAiDone` 接收流式回复。
- 通过 `api.aiChat(chatMessages, provider, lang)` 发起对话请求。
- 通过 `api.getConfig()` 读取配置，`api.saveSettings({ ai: { provider } }, [])` 保存默认模型。
- 通过 `api.memoryList()`、`api.historyList()`、`api.historyAppend()` 管理记忆与对话历史。

以 `settings.js` 为例：

- 通过 `api.getConfig()` / `api.saveSettings(patch, dirty)` 读写配置。
- 支持标签页切换（NAS / AI / 采集 / 软件 / 关于），语言切换后记住当前标签页。
- 调用 `api.saveDevice()`、`api.deleteDevice()`、`api.testNasConnection()`、`api.sshConfirmTrust()`、`api.clearCredential()` 管理设备与凭据。
- 调用 `api.memoryClear()`、`api.memoryDedupe()`、`api.historyClear()`、`api.chooseMemoryDir()`、`api.memoryList()`、`api.memoryDelete()` 管理 AI 记忆与对话历史。
