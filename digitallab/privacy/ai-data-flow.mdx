本页详细说明 AI 助手产生的数据类别、存储方式、请求组成以及数据离开本机的条件。内容依据 v1.6.0 代码整理。

<Note>
  AI 助手当前为对话模式，**不包含 Agent 工具调用能力**：请求中不携带工具定义，模型不能调用本机工具。仓库中的 `core/agent_tools.py` 目前没有开放给模型使用。
</Note>

## 收集的信息（AI 相关）

DigitalLab 在本机采集或生成以下与 AI 相关的信息。

### AI 对话历史

你与 AI 助手的对话内容（仅在你主动使用 AI 功能时产生）。默认保存在本机文件 `%APPDATA%\DigitalLab\memory\chat_history.jsonl`，重启应用后恢复；可在设置面板的"对话历史"中设置保存开关、保留条数上限（20 至 5000，默认 200，超出后按最旧裁剪）或一键清空。

- 关闭"保存对话历史"只是停止把新消息写入该本地文件，不会删除已有记录（需手动清空或删除文件）。
- 关闭"保存对话历史"不会停止 AI 请求：你当前发送的消息与会话内已有的对话内容仍会随本次请求发送给所选 AI 服务。
- 对话历史文件本身不会被整体上传到任何服务器。

### AI 记忆（可选，默认关闭）

仅在你在设置中开启记忆后，你在对话中明确表达、值得长期记住的偏好（如称呼、设备名、使用习惯）会持久化保存在 `%APPDATA%\DigitalLab\memory\ai_memory.jsonl`。

- **写入**：模型回复中带有记忆标记的内容会被提取，每轮回复最多提取 3 条，每条最多 500 个字符；记忆标记总会从显示的回复中去除，但只有开启记忆时才会写入文件。
- **注入**：开启记忆时，每次请求注入最近 10 条记忆的内容，每条截断到 200 个字符。
- **离开本机的条件**：开启记忆并使用远程模型时，注入的记忆内容会随请求发送至该服务。
- **关闭记忆后**：不再写入新的记忆，已保存的记忆文件不会被读取或注入对话，但文件本身仍保留在本机，需在设置中删除或清空。

### AI 请求上下文（仅在使用 AI 功能时生成）

后端每次组装的消息列表（JSON 请求正文中的 `messages`，也就是模型可见的上下文）包含四部分：

1. **静态提示词**：角色设定、使用规则、输出格式约束；开启记忆时还含记忆指令。
2. **记忆内容**：仅开启记忆时，最近 10 条，按时间与标识确定性排序。
3. **实时系统状态摘要**：CPU/内存/磁盘使用率，CPU/GPU/内存/硬盘的型号与容量，已配置 NAS 设备的名称、在线状态、CPU/内存/磁盘占用与温度。
4. **对话内容**：你当前发送的消息与会话内已有的对话，后端只保留最近 16 条。

以下信息**不进入模型上下文**：NAS 主机地址与登录凭据、完整进程列表与命令行、日志内容、AI 记忆的标识/类别/标签/来源字段、API Key。

**AI 记忆与对话历史是两个相互独立的功能**：记忆开关控制长期记忆的读取、注入与持久化，默认关闭；对话历史保存开关控制本地聊天记录写入，默认开启。关闭其中一个不会关闭另一个，也不会停止 AI 请求。

## 一次请求包含什么

一次 AI 请求由 HTTP 请求头和 JSON 请求正文两部分组成，二者承载的内容不同：

| 部分 | 内容 | 模型能否看到 |
| --- | --- | --- |
| HTTP 请求头 | `Content-Type: application/json`；云端模型另加 `Authorization: Bearer <API Key>` | 否，仅供服务端认证 |
| JSON 请求正文 | `model`（模型名）、`messages`（上文四部分上下文）、`stream: true` | `messages` 即模型上下文 |

API Key 会随每次云端请求发送给你配置的端点，但只出现在 `Authorization` 请求头中，不写入 JSON 请求正文、提示词、系统消息或对话内容。发往 Ollama 的请求不带 `Authorization` 请求头。

## 模型选择与数据去向

| 项目 | Ollama | 云端模型（OpenAI 兼容 API） |
| --- | --- | --- |
| 默认地址 | `http://localhost:11434`（可在设置中修改） | `https://api.deepseek.com`（可在设置中修改） |
| 默认模型名 | `llama3` | `deepseek-chat` |
| 请求路径 | `{base_url}/api/chat` | `{base_url}/v1/chat/completions` |
| 数据是否离开本机 | 使用本机地址时否；改为其他主机时，请求发往该主机 | 是，请求发送至你配置的服务端点 |
| API Key | 不发送 | 必填，以 `Authorization: Bearer` 请求头发送 |
| AI 对话历史存储 | 本机 `chat_history.jsonl` | 同左，历史始终存本地 |
| AI 记忆存储 | 本机 `ai_memory.jsonl` | 同左，记忆始终存本地 |
| 模型上下文范围 | 静态提示词、记忆（若开启）、实时系统状态、最近 16 条对话 | 同左 |

两种模型的地址都受同一套 [AI 端点传输策略](/digitallab/privacy/sensitive-information#ai-端点传输策略) 约束：

- 远程 HTTPS 允许，并使用默认 TLS 证书校验；可用 `ai.ca_bundle` 指定自定义 CA，文件缺失或不可读时请求失败。
- loopback HTTP 允许。
- 私网与 Tailscale 地址的 HTTP 需要在 `ai.allow_insecure_http` 中按 `ip[:port]` 精确授权。
- 域名、公网 IP、link-local 与云元数据地址的 HTTP 一律拒绝。
- 请求不跟随 HTTP 重定向。

## 请求流程

<Steps>
  <Step title="用户输入">
    你在 AI 助手面板输入消息并发送。
  </Step>
  <Step title="上下文组装">
    后端组装模型上下文：静态提示词、记忆内容（若开启）、实时系统状态摘要、最近 16 条对话。
  </Step>
  <Step title="端点检查">
    后端按 AI 端点传输策略检查所配置的地址，不符合策略的请求直接失败，不会发出。
  </Step>
  <Step title="发送请求">
    使用 Ollama 时，请求发往你配置的 Ollama 地址（默认本机 `localhost:11434`，此时数据不离开本机）。使用云端模型时，请求发往你配置的 `base_url`，API Key 放在 `Authorization` 请求头中，数据由该服务处理。
  </Step>
  <Step title="本地记录">
    对话内容根据"保存对话历史"开关决定是否写入本地 `chat_history.jsonl`；开启记忆时，回复中的记忆标记会被提取写入 `ai_memory.jsonl`。
  </Step>
</Steps>
